# September 2026

## 2026-09-13: Watched the defect channel drain a backlog for the first time
**Learned.** Three weeks ago I built an outbox where any read-only job can file a fixable finding, because the same one-line fixes kept getting narrated in report after report and applied in none of them. Sunday it ran against a real backlog: 19 open findings triaged, 8 applied and verified, and the remaining 11 escalated to me rather than guessed at. The applied set included a guard on a read that returns a healthy status with zero rows, and the sweep reproduced that false zero live before it changed anything, so the fix was written against the actual failure instead of against my description of it. The same morning a separate auditor probed five connectors, got real data back from all five, and still surfaced three silent failures sitting behind them. A channel that can only file findings is a queue, and a queue with nothing authorized to drain it fills at exactly the rate you produce problems.

## 2026-09-10: Took the grading seat back from the thing being graded
**Decided.** My resume product got an eval harness on Wednesday, and on Thursday I stopped my own assistant from both writing the test cases and scoring them, because a grader authored by the same system it grades carries no independent check anywhere inside it. Reading the failures by hand is what proved the point: the first scoring pass put groundedness at 0 to 40% across most call sites, and roughly half of those failures turned out to be the grader's own noise, including "$95K" failing to match "$95,000", "B2B" parsed as 2 billion, and a sentence saying "I don't have an MBA" flagged as claiming an MBA. Those corrections went back into the grader and the stored outputs were re-scored for free, and what survived is either a real defect or one of three grader limits I wrote down by name. I also measured the noise floor, roughly 20 points on a pass rate at this sample size, so I stop reading meaning into differences smaller than the measurement error. A number nobody checked by hand is a claim the measuring instrument is making about itself.

## 2026-09-09: Made my product fail loud before making it faster
**Shipped.** I put my resume product through a full cycle in one sitting: an assessment-only read of every place it calls a model, then a real eval harness with golden cases and three separate graders, then 14 commits against what the first two turned up. Almost every fix was the same move, which is that a step unable to do its job now throws instead of returning something plausible. Profile extraction rethrows rather than handing back a partial profile, scoring throws on a missing tier rather than defaulting to one, analysis throws when a genuine job description yields zero requirements, and a model that runs out of output tokens mid-sentence throws rather than shipping a truncated resume as a finished one. I also switched the SDK's automatic retries off and set an explicit timeout, so a hang surfaces as a hang. Anything that generates text for a person can fail by producing the right shape with the wrong content, that failure is invisible to every step downstream, and the only place it can still be caught is the step that knew what it was supposed to produce.

## 2026-09-08: Changed the document so I would stop reformatting it by hand
**Shipped.** My interview prep guides are generated as markdown and uploaded straight to Drive, and they had been landing with their structure destroyed, so every single one cost me a round of manual cleanup on the far side. The cause was two formatting habits the generator had no reason to question, blockquotes and fenced code blocks, neither of which survives a markdown upload into Drive. I replaced them with bold labels, indented lists, and a plain visible marker showing where to start copying, pushed the same convention into the agent definition, the skill that calls it, and two memory files so nothing regenerates the old shape, then confirmed it with a real upload and read-back instead of assuming. The version of this fix I had actually been running since July was to repair the output by hand every time, which works on every run and teaches the generator nothing. When the same cleanup shows up after every run, the thing to change sits upstream of the output.

## 2026-09-07: Found my job scout pointing at the wrong jobs
**Learned.** My automated role scout pulls job listings out of email alerts, and it built each row by pairing a list of job IDs against a list of job cards by position. That holds right up until the two lists stop being the same length, which happens the moment one posting matches two of my saved alerts, and from that row onward every link points at a different job than the text above it. Four of 35 rows in that morning's digest were wrong this way, and none of them looked wrong: real title, real company, real link, all correctly formatted, none of them describing each other. The rows were corrected by hand before the digest went out, and the parser fix itself is still sitting behind my review. Aligning two lists by index is an unstated assumption about both of them, and when it breaks the output stays perfectly well formed, which is why nothing downstream is ever going to catch it for you.

## 2026-09-05: Rescoped a writing rule around where the writing ends up
**Decided.** I keep a standing ban on em-dashes in anything written in my voice, and it had quietly widened past its purpose: the rule named no destination and the memory file behind it said every deliverable with no exception, so it was burning edit passes on research notes and worksheets that nobody but me will ever read. I rescoped it by destination, banned in anything that leaves my hands (emails, posts, website copy, resumes, cover letters, outreach, client work) and allowed in the material my tooling writes for me to read, then pushed the same wording through all four places the rule lives. Resumes and cover letters stay banned, since a resume was the original failure the rule got written to stop. The detail that settled it is that the automated check actually enforcing this had been scoped to resumes, cover letters, final drafts and outreach the entire time, and it needed no change at all. When a written rule and the code enforcing it disagree about scope, the code is usually describing the problem you really had.
