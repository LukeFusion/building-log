## 2026-11-08: Caught my tracker sync calling a broken read safe
**Learned.** Each morning a job exports my application tracker spreadsheet, runs a validation script against the last good snapshot, and replaces the snapshot only if the script says the new copy is safe. I had renamed one column header in the sheet by hand, so the script read every application number as blank, reported every row as new and every old row as gone, and still returned ok with an empty problems list, because its checks for a cut-off export depend on those same numbers and went blind when they vanished. The agent running the job refused to commit anyway, since a diff in which the entire sheet changed overnight describes a broken read, and it emailed me the cause. On Sunday I made the script accept both header names and block on its own when a required column is missing or when more than 10% of the application numbers disappear, confirmed that a copy with the renamed column now blocks, and then ran the real sync, which committed and matched the export byte for byte. A validator only knows the failures it was written to imagine, and the check that saved this run was someone reading whether the output made sense.

## 2026-11-02: Sized my job scout's daily batch from the list it has to cover
**Shipped.** Besides reading job alerts from my inbox, my job scout checks the career pages of the companies I track directly, and it did that in a fixed batch of 10 companies per weekday run. With 86 companies on the list, one full pass took nine runs, and nothing ever reported the lag, because every run checked its 10 pages successfully. On Monday I replaced the fixed number with the size of the list divided by three, rounded up, so every company gets checked at least once every three runs and the batch grows on its own as I add companies; at 86 companies that means 29 a run, and I raised the job's time limit from 20 to 30 minutes to fit. The first run at the new size added 24 rows and turned up 14 new jobs, and it named six career pages it could not read. A fixed batch size is a silent assumption about the length of the list, and the list kept growing while the assumption stayed put.
